# Red-team harness

Runs curated attacks against real mechanisms and records the refusals. Part of the [factory plane](README.md#factory-plane).

- **v1:** a Job that launches an adversarial agent or scripted action per attack.
- **v1:** Martin launches spec 5.3's attacks, each from its guardrail's row in the console, one at a time and with no passkey, through the [admin service](ADMIN-SERVICE.md#a-red-team-attack), which opens the attack's work item with his `attack.launched`. What each tries, the refusals it expects in order, how long it may take before it counts as unfinished, and whether it can be launched yet are [`policy/attacks.ts`](../../policy/attacks.ts)'s. Three can: the report (`report`), data to an outside URL (`egress`) and the image it built itself (`image`). Two are not available yet, editing a workflow (`workflow`) and the pull request that deletes a test (`test`): they stay in the catalogue, and the admin service refuses their launch. The harness records how an attack ended as `attack.finished` on that work item, as its own role, `factory_redteam`, alone may ([event store](EVENT-STORE.md#martins-commands)). Each attempt says whether it was refused, and an attack is refused only when every one was. The egress attack also reaches the gateway, which its pod may, as its control, recorded apart from its attempts: a control that fails proves nothing of the refusals, so that attack is unfinished, not refused.
