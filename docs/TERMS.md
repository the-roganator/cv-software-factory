# Terms

The words we use, so docs, code, UI and commits stay consistent. Standard industry terms are not defined here; only our choices are.

| Use | Not | Meaning |
|---|---|---|
| **Software Factory**, **the factory** | dark factory | The product name, and the system in prose: agents, gates, delivery and console. Web pages are titled "Software Factory · Martin Rogan". Avoid "dark factory": it is an industry term we do not use. |
| **console** | command centre, dashboard, control panel | The factory's web UI for visitors and admin: the line, the reel and its sheets, scoreboard and controls. |
| **reel** | carousel, timeline, feed | The console's row of work items, one card each, oldest on the left and now on the right, scrubbed sideways to watch the app change. |
| **sheet** | drawer, modal, detail view | The panel that rises from the bottom of the console when a card in the reel is opened: one work item in full, from its stage scrubber to its model calls. |
| **human** | person, people, user | Anyone who is not an agent, as in "held for a human" or "code written by humans". Use **Martin** when it can only be him, and **visitor** for someone with a visitor key. |
| **Kubernetes** | k8s, kube | The orchestration platform, in prose. Name a specific distribution (k3d, DOKS, EKS) only when the difference matters. |
| **stage** | step, phase | One part of the factory's line: sense, triage, plan, build, gates, review, release, verify. A feature flag has stages of its own: say "a flag's stage" for those. |
| **the line** | conveyor, workflow | The eight stages in order, and their drawing across the top of the console; the line's worker (`factory line`) carries work items through them from Plan, past Martin's merge, through Release and Verify until each closes. "Stop the line" halts all of it. "Pipeline" means CI only. |
| **station** | node, card | The drawing of one stage on the console's line. |
| **Needs you** | approvals, queue | Work waiting on Martin, and the console panel that lists it. Not the inbox, which holds signals for triage. |
| **admin** | administrator, superuser, operator | Martin signed in: the role the access table (`policy/access.ts`) gives his session, and what only he may do with it. The **admin service** (`factory admin`) is the one way a browser changes the factory; "admin mode" in the spec is the console as his session sees it. Everyone else is a **visitor**, and sees every control read-only. |
| **passkey** | password, security key, login | Martin's only way to sign in: a WebAuthn credential on his laptop or phone, unlocked by the device's own check, at most two held at once. One is added only with a one-time code `make enrol` prints, never from a session. |
| **step-up** | re-authentication, sudo, MFA prompt | Giving the passkey again within a session, for an action that loosens a control, raises spend, promotes something or overrides a guardrail (starting the line and retrying a stopped release among them), and to revoke a passkey; it counts for five minutes. The console calls it "Your passkey, again", and marks each action that asks with a key. |
| **setting** | preference, config, option | One of **Martin's settings**: an agent's model and effort, or a spend cap, chosen on the console's settings page within the bounds policy sets, each save that changes something one `settings.changed`. A worker's own settings are its variables, in the Settings table on its component's page, set on its Deployment and changed by a deploy pull request: say "Martin's settings" for his. |
| **controls** | toggles, options, config | **The line's controls:** the autonomy level, the switches (agents take new work, auto-merge of low-risk changes) and what the line takes, each change one `controls.changed`. **Alerts to the phone** is a switch of its own in Controls, each switch one `alerts.switched`. The **canary's controls** are Martin's promote, pause, abort and retry of a release in flight. Neither is a setting. |
| **work item** | job, task, run | One piece of work through the line (a defect fix, injected defect, improvement, dependency update, red-team attack or visitor report), from its first event to its last. |
| **event** | log entry, message | One step of a work item, or of the line, as the event store keeps it: an envelope and a typed payload. |
| **public view** | redacted copy | What anyone but Martin may see of an event, written once when the event is appended. It never carries what a visitor wrote, their key, or anything shaped like a secret. |
| **event log** | dump, fixture, export | A folder holding public events as newline-delimited JSON, beside their artifacts named by hash. Samples, recordings for the replay site and the console's tests are event logs. |
| **projection** | view model, state | What the console draws, worked out from events and a time *t* by `project(events, t)`. Live view and replay are the same projection at different times. |
| **sample** | fixture, mock, demo data | A hand-written work item that shows what the console will show. Every sample says it is one; a store holds samples or real events, never both. |
| **artifact** | attachment, asset | A file captured with an event (a screenshot, a gate's output), named by the SHA-256 of its contents and never changed. |
| **milestone** | stage, phase, step | One unit of the delivery plan in `PLAN/`. |
| **the app** | the site, the shop (in factory docs) | The World's Worst Website, the web app the factory looks after. "The shop" is what the app calls itself to its visitors: Mossop's Practical Sundries. |
| **defect** | bug, issue, fault | Something wrong with the app that the factory should find and fix. A **seeded** defect was in the app's first commit; an **injected** one arrives later, through the injector. |
| **answer key** | defect list, catalogue | The private list of every seeded and injectable defect: category, difficulty, location, symptom, fingerprint and expected sense. Only the scoreboard reads it. |
| **fingerprint** | signature, ID | What identifies a defect from outside: a route and a symptom class, or, for content, a page and the exact text that is wrong. The scoreboard matches a ticket to the answer key by fingerprint alone. |
| **scoreboard** | score, leaderboard | The service that counts tickets against the answer key, and its figures beside the app's name: **found** (entries a ticket matched), **verified fixed** (entries whose matching ticket closed as verified) and the median time from a ticket's first signal (or its opening, with none) to its verified fix. A **false positive** is a ticket that matches no entry, a drill's included; those are published only with the results. |
| **symptom class** | error type | One of a short closed list of ways a defect shows itself, such as `broken-link` or `slow-response`. The answer key and tickets share the list. |
| **sense** | detector, monitor | One of the six ways the factory notices a defect: probe, crawler, metrics, logs, the canary or a report. The **canary** as a sense is its analysis: each measure that fails a release is its signal. |
| **check** | test, assertion | One thing a sense looks at, such as "search finds a product by a word in its name". A check that passes writes nothing; one that fails twice in a row sends a signal. |
| **signal** | alert, event | What a sense found, a visitor reported, or the planner noticed outside its ticket (its findings): the route, the symptom class and the evidence, or for a report or a planner's finding its words, which triage judges and no public view shows. Signals wait in the inbox until triage takes them, and only those triage keeps become events. |
| **inbox** | queue, backlog | The table where signals wait for triage. Only the factory reads it, because reports are in it. |
| **ticket** | issue, bug | A defect triage has recognised, with its category, severity, fingerprint and evidence. One fingerprint, one ticket; a ticket closes only when its fix is verified, and **reopens** when its signal returns. The GitHub issue the App opens when work on it starts is the ticket's issue. |
| **spec** | plan, requirements | What the planner writes for one ticket: the outcome, Given/When/Then acceptance criteria, each naming what in the ticket's evidence asks for it and quoting its words, the files that may change (its scope), risk tags and a rollout note. "Spec section 4.1" means a section of `SPECIFICATION.md`. |
| **step** | job, attempt | One agent's turn at one work item, in a runner: the planner's step, the coder's second round. A stage may take several steps, and a step that fails runs again as a new one. |
| **round** | iteration, loop | One pass from the coder to the gates and review. Failing gates or a review's blocking findings send the work back to the coder for the next round, as many times as the line allows before it holds; an approval's suggestions send it back once. |
| **runner** | sandbox, container, agent | Where a step runs: a Kubernetes Job that checks out the repository, then one that runs the agent and reaches only the gateway and the handback, with a job token as its only credential. GitHub's are always "GitHub-hosted runners". |
| **handback** | result, callback, response | What a runner sends the line when its step ends: the patch, the agent's note, its turns and session, and the result the step asked for. Also the line's endpoint that takes it. |
| **patch** | diff, commit | The change a coder hands back, as data: everything changed since the step's commit. The GitHub worker commits it outside the sandbox. "Diff" is what a pull request shows. |
| **scope fence** | path check, allow-list | The deterministic check that refuses a patch changing a file outside its spec's scope, or under `.github/` or `deploy/`, or one a CODEOWNERS file gives a person. |
| **gate** | check, CI, test | A deterministic check a change must pass before it can merge: a required check on `main`, such as tests, test integrity or journeys. A model is never a gate: the reviewer's check run is a signal. **Gates** is also the stage that waits for them. A sense's **check** is something else. |
| **journeys gate** | e2e tests, smoke test | The gate that runs the probes and the crawler against the base's app and the change's, and fails only on a check that passes on the base and fails on the change. The app is broken on purpose, so judged alone every change would fail. |
| **hold** | block, pause, escalation | A work item waiting for Martin, with a cause (the scope fence, the gates, the review, a merge, a deploy, Verify, the spend cap and others) that says what each of his answers does. Holds are what **Needs you** lists. A **wait** is not a hold: a work item whose spec shares a file with work in flight waits for that work to be verified or closed, which needs nobody. |
| **dry run** | simulation, mock mode | The GitHub worker writing what it would have done to the artifact store and touching nothing in GitHub, while answering for its own pull requests: their checks pass, and they merge a while after they are readied, so a line in `dry-run` goes round. Such a merge never ships, so the line releases and verifies it by the dry run's word, and each of those events says `dryRun`. |
| **soak** | load test, burn-in | The line left running unattended on the local model, with the GitHub worker in a dry run, and read the morning after (`factory line soak-check`): no lease stuck, no runner left, every event valid, nothing spent. |
| **seeded baseline** | initial state, golden copy | The app's tree as first published: the correct app with every seeded defect applied. Reset restores it. Not a canary's **baseline**. |
| **canary** | preview, beta, blue/green | A new version of the app while its release is in flight: it runs beside the version it replaces, takes part of the app's traffic, its **weight** (a quarter, then half), and is judged against its baseline at each step and throughout. It **promotes** itself to all of the traffic when every judgement passes. Only the app has canaries. |
| **baseline** | control, previous version | The version a canary is compared with: the stable version, which is all of the app between releases and keeps the rest of the traffic during one. Not the **seeded baseline**. A **flag's baseline** is Verify's run of the probes with an improvement's flag off, its pages pictured in light and in dark, which the journeys at Checks and Preview, and the pictures at Checks, are compared with. |
| **weight** | share, percentage, split | The part of the app's traffic a canary takes, as a percentage. Each of its steps sets one, and a rollback or an analysis error records the weight it had reached. The **split** is the two versions' weights together, which Argo Rollouts sets in Traefik. |
| **rollback** | revert, undo | A canary's analysis failing, and Argo Rollouts sending all the traffic back to the baseline, with nobody touching anything. Nothing changes in Git: the bad commit stays on the app's `main` until a fix or a revert merges. A **revert** is a commit; a rollback is not. Each measure that failed is a signal from the canary, so a rollback opens a ticket. |
| **analysis error** | failure, abort, inconclusive | A canary's analysis ending in Error: it could not take its measures (Prometheus did not answer, say), so it could not judge the canary, and Argo Rollouts stopped the release itself, sending all the traffic back to the baseline. Nothing failed, so it is no rollback and no signal; nobody stopped it, so it is no abort. The line records it as `release.errored`, with the analysis's words and the measures it could not take, and the console says "stopped by an analysis error". It stays stopped until Martin retries it or a new deploy starts another release. |
| **abort** | rollback, cancel | Martin stopping a release in flight, from the console's Canary panel, with Stop the line (the console's header, or `make stop-the-line`), or by hand: the baseline takes all the traffic, as in a rollback, but nothing failed, so it is no signal. The line records it as `release.aborted`, saying which. It stays aborted until he retries it or a new deploy starts another release. Argo Rollouts says "aborted" for a rollback and an analysis error too; we do not. |
| **release** | launch | One version of the app going out through its canary, from its start to its promotion, rollback, analysis error or abort, named by the canary's pod-template hash and the Rollout's revision, so a later release of the same image is a release of its own. It **carries** every merged work item whose fix is in it and not in the version before; one that carries none is on the line itself. **Release** is also the stage. Not the release release-please tags and publishes, which names a version and runs nothing. |
| **found live** | backfilled | A release the line did not watch: the version already stable when the line first saw it, recorded with `watched: false`, so the work items whose fixes it holds go on to Verify. |
| **verification** | validation, confirmation | Verify's look, after a release is promoted, at whether the ticket's defect has gone from the new version, asked of the sense that first saw it: its check run again, its alert's expression, its log pattern or the log watcher's agreement check over the new version alone, or the canary's measure. It finds that the signal has **cleared** or **persists**, and **verified** is a work item closed because it cleared, or because Martin judged that it had; an improvement is verified once its flag is on for everyone. A ticket only a report saw holds for Martin, since no sense can look again. A held or waiting work item is **looked at again** the same way after a release that did not carry its fix, and one whose signal has cleared there can close as verified too. |
| **reopen** | regression ticket, duplicate | A verified ticket's signal returning: the same ticket, work item and issue open again and go back to Plan, rather than a new ticket for the same defect. Only a ticket closed as verified reopens, and only a sense's signal reopens it. A signal on a ticket a dry run verified, whose fix never shipped, is counted on that ticket, as one from before the close is: nothing reopens and no new ticket opens, until the line runs live and reopens it itself. A signal that persists at Verify does not reopen anything: the ticket never closed. |
| **pictures** | visual diff, snapshots | Every page of the app screenshotted on the stable version and on the canary while a release runs, and each pair compared pixel by pixel; at Verify, "every page against the version before", the ticket's own page marked intended. Snapshots are the console's visual tests. |
| **improvement** | feature request, enhancement, suggestion | Something new Martin asks for with the "+" in admin mode, in his own words: a work item of kind improvement, planned, built, reviewed and released as a fix is, and shipped switched off behind a flag of its own. A visitor's **suggestion** is not one, and starts no work. |
| **feature flag**, **flag** | toggle, switch, feature toggle | A name the app asks about, request by request (`await request.flag('<flag>')`), to decide whether an improvement's new behaviour shows. The improvement's spec names it; its stage is Martin's, kept in `flags` in `flagd`, which flagd serves to the app. `flag-set-revision` is a flag but not a feature: it names the flag set, and is never on. |
| **a flag's stage** | ring, rollout step, stage 1 | Who a flag is on for, each keeping the ones before it: **Off** (nobody), **Checks** (the factory's own checks, by the mark), **Preview** (and browsers that asked to preview it), **Share** (and a share of the traffic generator's requests) and **Everyone**. Martin **widens** and **narrows** a flag from the console's Flags panel, one move at a time. |
| **the mark** | test header, bypass | The header `x-unmeasured`, which the factory's own requests send: it keeps them out of the figures a canary is judged on, and a flag at Checks is on for them. The network keeps it: Traefik removes it from every request through the front door, and only the pods the app's network policy names reach the app any other way. |
| **preview** | beta, opt-in, early access | A flag at Preview, on for a browser that asked with `?preview=<flag>` on the app, which the app remembers for a day in its **preview cookie**, the one thing flags keep on a visitor's device. The console's "Preview it" opens that link. Not a **canary**. |
| **share** | cohort, split, weight | The part of the traffic generator's signed requests a flag at Share is on for, 10, 25 or 50%, chosen by flagd's rule over the id each carries. Visitors are never in a share. Not a canary's **weight**, which splits the app's traffic by version. |
| **hand-over** | done, finished | The line passing an improvement to its flag once a release that carries it is promoted: its row on the line ends, and its work item stays open until its flag closes it. |
| **comparison** | A/B test, experiment | Verify's judgement of a flag at Share: the requests it was on for against those it was off for, on errors and latency, from the traffic generator's own figures and with the canary's thresholds. Everyone waits for it to pass. |
| **kill switch** | rollback, revert | Turning a flag Off, from any stage, which reaches the app within seconds with no deploy. Below Everyone it closes the improvement as **turned off**. Nothing is rolled back: the code stays in the app, off. |
| **TypeSafe** | | The company and API that serve Jev. |
| **Jev** | classifier, LLM | TypeSafe's model for typed judgements: it answers Choice, Score and Noul questions with probabilities and never generates text. |
| **question set** | prompt | A versioned group of Jev questions, such as `triage/v2`, kept as code. |
| **cassette** | recording, tape, mock | One model call as the gateway recorded it: the request and the provider's response, in a file named by the SHA-256 of the provider, model and request. Replaying it answers the same request again without calling the model. "Recording" means an event log. |
| **bench** | harness, playground, test rig | One agent's step run on a developer's machine against a gateway on the host, on a fixture of invented work, to work on that agent's prompt (`factory line bench`): on Qwen for nothing, on Claude to record cassettes, then from the cassettes. It runs the runner's own steps, without the runner's fence. |
